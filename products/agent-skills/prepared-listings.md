## Repository Feature Map

Source: [repository-feature-map](repository-feature-map/SKILL.md).
Logo: [repository-feature-map.png](marketplace-assets/icons/repository-feature-map.png).

Summary: Trace existing feature ownership, contracts and tests before adding code. Get a scoped reuse decision and an evidence-linked documentation plan.

Description: Help your agent find the implementation that already owns a capability. Trace one user flow through contracts, services, provider adapters, jobs, durable state and tests. Separate source evidence from deployment assumptions, identify contradictions and propose the narrowest change. Includes a feature brief, capability-index row, discovery method and fictional worked example. Works with authorized repository access or supplied snippets; snippet-only maps remain provisional. No automatic commits or deployment.

Suggested primary category: Technical Documentation. Secondary: Code Quality & Review. Tags: feature-map, repository-analysis, documentation, architecture.

Compatibility: Markdown-reading agent. Repository discovery requires the host's authorized file/search tools. No required network, API key or account. Baseline use reads files; requested documentation updates may write scoped repository files. Other agents have not been independently tested.

## Evidence-Led Product Planning

Source: [evidence-led-product-planning](evidence-led-product-planning/SKILL.md).
Logo: [evidence-led-product-planning.png](marketplace-assets/icons/evidence-led-product-planning.png).

Summary: Turn feature requests into focused decisions, small PRDs and measurable validation plans while keeping evidence, assumptions and unknowns separate.

Description: Give your agent a practical path from a broad idea to a decision you can review. Compare reuse, a narrow new slice and validation where relevant. Define scope, acceptance, failure recovery and a metric with an explicit denominator. Avoid invented demand, fabricated prioritization scores and unsupported growth promises. Includes decision-brief and PRD templates, an evidence method and a fictional worked example. Planning does not activate experiments, contact customers or implement features.

Suggested primary category: Business & Operations. Secondary: Research & Analysis. Tags: product-management, prd, mvp, prioritization.

Compatibility: Markdown-reading agent with supplied product evidence. Optional file/research access depends on the task; no specific analytics service or connector is required. Output can stay in chat or be saved to an authorized destination. No measured business-results guarantee.

## Docker Compose Release Planner

Source: [docker-compose-release-planner](docker-compose-release-planner/SKILL.md).
Logo: [docker-compose-release-planner.png](marketplace-assets/icons/docker-compose-release-planner.png).

Summary: Assess Compose release readiness with explicit backup, schema-compatibility, acceptance and recovery gates before an operator touches production.

Description: Turn sanitized deployment evidence into a go/no-go release record and an operator handoff. Distinguish healthy containers from a ready release, a VM snapshot from a verified data recovery path, and application rollback from schema recovery. Define user-visible acceptance and side-effect limits. Includes release/recovery templates, a readiness method and a fictional blocked-release example. This is a planning package and executes no deployment, migration, restore or infrastructure purchase.

Suggested primary category: DevOps & Cloud. Secondary: Testing & Debugging. Tags: docker-compose, release-planning, backup, rollback.

Compatibility: Markdown-reading agent and supplied sanitized runbook/configuration evidence. Optional read-only tools are host-provided. No infrastructure credentials, scripts or network permissions required for supplied-text analysis. Fictional planning validation only; no live deployment or recovery certification.
