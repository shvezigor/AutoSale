# Readiness evidence map

| Gate | Evidence to collect | What it does not prove |
|---|---|---|
| Path/version | Current official docs and configured login/API path | Another path's permissions apply |
| Actor eligibility | Account type, app role, invitation acceptance and access level | Tester success means every customer can connect |
| OAuth | Safe stage/category, matching redirects, state/code lifecycle | A generic error identifies the failed exchange |
| Webhook | Subscription, challenge, signature verification and event processing evidence | Challenge success proves real-event receipt |
| Reviewer path | Stable URL, actual working review actor and screencast steps | An untested credential or 100% dashboard indicator works |
| Data handling | Owner-verified processors, purposes, retention and deletion | Text generated by an agent reflects actual practices |

Official starting points, to verify for the selected integration and date:

- [Instagram Platform](https://developers.facebook.com/docs/instagram-platform/)
- [Instagram API with Instagram Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/)
- [App Review](https://developers.facebook.com/docs/app-review/)

These are discovery links, not frozen provider requirements. This package intentionally does not prescribe a universal permission list. If official docs are inaccessible, retain an explicit verification gap. Read-only analysis can still map supplied evidence and formulate the exact question.

Acceptance plan: actual reviewer login; each permission's visible use; test and non-role actors kept distinct; callback failure stage diagnosed without secrets; signed event ingestion and downstream effect; revocation/deletion; no production messages without approval.
