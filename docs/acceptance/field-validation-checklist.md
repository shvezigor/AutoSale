# Приймання польової валідації форм

Оновлено: 2026-09-24. Канонічна поведінка: [специфікація](../superpowers/specs/2026-09-21-field-validation-ux-design.md).

## Автоматизована перевірка

- [x] Усі 1501 unit/contract/component тести проходять; `pnpm typecheck` та `pnpm build` успішні.
- [x] Репозиторний контракт інвентаризує production-форми; лише два Google Picker сценарії мають задокументований non-field виняток.
- [x] Публічна демоформа в Playwright показує помилки під полями, переводить фокус, зберігає введені дані та очищає лише виправлену помилку.
- [x] На ширинах 320, 768, 1024 та 1440 px демоформа не створює горизонтального скролу.
- [x] `aria-invalid` та `aria-describedby` покриті компонентними тестами для спільного поля.

- [x] 2026-09-23: після ручного Docker-релізу коміту `0e03886615677a4824e7659bb7ac2131b7a6830c` сервіси `api`, `web`, `worker` здорові; `/health/live`, `/login`, `/uk/demo` повертають HTTP 200. Prisma перевірила 42 міграції, нових немає.
- [x] Перед релізом створено локальну резервну копію `20260923T084613Z`; SHA-256, читаність PostgreSQL dump і MinIO archive перевірені. Копіювання поза поточний хост та окремий test-restore цим релізом не виконувались.
- [x] Безпечний Playwright-тест некоректної демоформи пройшов безпосередньо на `https://sales-aito.com` на 320/768/1024/1440 px; запит із даними не надсилався.
- [x] 2026-09-23: у відокремленому браузері Codex на production-сторінці реєстрації порожній submit показав чотири польові помилки, сфокусував перше поле та зв'язав контролі з текстом через `aria-invalid`/`aria-describedby`. На 320 px горизонтального переповнення немає; виправлення імені прибрало лише його помилку. Реєстрацію не завершували.
- [x] Резервну копію `20260923T084613Z` відновлено у тимчасовій PostgreSQL без доступу до мережі: 56 таблиць. Архів MinIO розпаковано у тимчасову файлову систему: 40 файлів. Тимчасові контейнери видалені; робоча БД не змінювалася.
- [x] Копію того ж backup з обмеженим локальним доступом збережено на окремому фізичному диску D:; SHA-256 усіх шести файлів збігаються з оригіналом. Це не є off-host копією.
- [x] 2026-09-24: в окремому авторизованому браузері порожній submit форми зміни пароля показав три польові помилки й сфокусував перше поле; усі три мають `aria-invalid` та `aria-describedby`. Порожня форма нового товару показала помилки артикула й назви, а введення вигаданого артикула прибрало лише його помилку. Товар не зберігали.
- [x] 2026-09-24: порожня форма банківського рахунку показала помилки назви та IBAN з фокусом на назві. Рахунок не створювали. На 768 px виявлено горизонтальне переповнення шапки на 36 px через неактивний placeholder пошуку; локальне виправлення має окремий регресійний browser-test.
- [ ] Завершити клавіатурну та screen-reader перевірку назв/описів форм реєстрації, профілю, товару, рахунку, оплати й ТТН у контрольованому сеансі. Часткові перевірки вище не закривають цей пункт.
- [ ] Перевірити ті ж форми на 320, 768, 1024 і 1440 px без створення реальних замовлень, оплат чи ТТН.
- [ ] Після релізу responsive-виправлення повторити live-перевірку шапки на 768 px. Форми факту оплати й ТТН залишаються неперевіреними в production: на наявному замовленні вони заблоковані до фіксації суми та готовності комплектації; не змінювати реальні дані лише заради smoke-test.
- [ ] Створити зашифровану off-host копію після вибору приватного сховища та способу незалежного зберігання ключа відновлення.

Не вводити production-токени, IBAN або персональні дані у тестові форми. Тести використовують лише явно вигадані значення.
