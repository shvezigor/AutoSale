# План інтеграції Укрпошти

Дата: 2026-09-12

## Рішення

Додаємо Укрпошту окремим адаптером до наявного нейтрального модуля доставки. Підключення не є OAuth: власник бізнесу отримує реквізити після договору з Укрпоштою і один раз вставляє їх у AutoSale. AutoSale шифрує весь пакет реквізитів і ніколи не повертає секрети у браузер.

Активне підключення працює лише в одному явно вибраному середовищі — `SANDBOX` або `PRODUCTION`. Це не дозволяє випадково змішати тестові й бойові UUID, штрихкоди та ключі. Для переходу на production власник замінює тестове підключення бойовим після acceptance.

## Послідовні етапи

### 1. Безпечне підключення

- Додати строгий контракт: середовище, eCom bearer, counterparty token, tracking bearer і counterparty UUID.
- Додати HTTPS-клієнт лише для офіційних hostnames, обмежені timeout/error codes і безпечну перевірку eCom-доступу.
- Зберігати пакет реквізитів одним зашифрованим документом у tenant-scoped `DeliveryConnection`.
- Додати owner-only картку підключення в `Налаштування → Доставка`; менеджери бачать лише стан і середовище.

### 2. Адреси й профіль відправника

- Додати кешований пошук населених пунктів та активних відділень через адресний класифікатор.
- Відкидати заблоковані або недоступні для доставки записи.
- Зберігати точні зовнішні ідентифікатори та зрозумілий snapshot адреси.
- Налаштувати відправника, телефон, відділення, платника й типові параметри місця.

### 3. Відправлення

- Створювати адресу й клієнтів, потім відправлення, з локальною idempotency до зовнішнього виклику.
- Зберігати shipment UUID, ШКІ, parcel UUID/ШКІ, вартість і eCom lifecycle.
- Дозволяти зміну/видалення лише в `CREATED` із повторною серверною перевіркою.
- Завантажувати PDF-ярлик через backend без секретів у URL браузера.

### 4. Відстеження й acceptance

- Використовувати окремий tracking bearer і починати polling лише після фізичної реєстрації.
- Обробляти batch не більше 50 ШКІ, зберігати сирі події та versioned mapping статусів.
- Пройти sandbox-сценарій, потім одне контрольоване production-відправлення без післяплати й одне з післяплатою.
- До завершення спільного acceptance Нової пошти, Meest та Укрпошти не вмикати production-створення відправлень.

## Контроль якості

- Усі нові поведінки створюються test-first.
- `token`, bearer, Authorization і зашифровані credentials редагуються з логів та telemetry.
- Timeout create не повторюється без reconciliation; читання й класифікатор мають bounded retry/backoff.
- Перевірки: contracts, integrations, API, web, повний typecheck/build і мобільний сценарій налаштувань.
